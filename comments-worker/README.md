# Comments service (prototype feedback)

A Cloudflare Worker with a D1 table that holds the comments reviewers leave on the gnycyouth.org prototype pages. Every page carries the Comments drawer from `assets/comments.js`; each comment belongs to a page and, when the reviewer picks one, to a content slot on it, named by the code from the content brief (`HM-05`, `PF-12`). `comments.html` lists every comment from every page.

- **Address:** none of its own. The service is reached only through the staff Worker's `COMMENTS` binding, at https://site-review.gnycyouth.org/c (behind the email sign-in).
- **Account:** the Greater New York Conference Cloudflare account, free tier. Database `gnycyouth-comments`. A copy of the Congress 2027 comments service, kept separate so the two prototypes do not share a table or a deployment. Moved on October 18, 2026 from Darwin Garcia's personal account (rdgt07), with the 24 comments that were live then, under their original ids; the old service and database stay there, unused; its public address was turned off on October 22, 2026, and it answers 404. The move was confirmed the same day: Darwin Garcia signed in at site-review.gnycyouth.org, the moderator key was set, and the first comments posted there carry the Verified staff mark. From the same day the older staff address gnyc.webtekton.com shows no comments, so nothing is posted into the old database.
- **Who can read:** only people signed in on the staff copy. Every read and delete needs the staff key, so the comments stay private even if the Worker is given an address by mistake. The public GitHub Pages copy shows no comments.
- **Who can post:** only people signed in on the staff copy (https://site-review.gnycyouth.org, Cloudflare Access email code). The staff Worker forwards each post over a service binding with the signed-in email and the shared secret `STAFF_KEY`; nothing a browser sends can set the email. The name shown comes from the staff directory, secret `STAFF_NAMES` (JSON, email to full name), so nobody types a name and nobody can post as someone else. A signed-in email missing from the directory may read but not post. Emails are stored (column `email`) for tracing and the per-person limit of thirty an hour, and never returned: reads carry only `verified`. Comments posted before October 17, 2026 have typed names and no `verified` mark.
- **What a comment may contain:** no web addresses, email addresses or phone numbers, including disguised forms; allowed are the conference's own gnycyouth.org and Google Drive or Docs file, folder and document links, which the drawer makes clickable. Tests: `node comments-worker/test/rules.test.mjs`.
- **Adding a person:** add the email to the Access policy "GNYC staff site reviewers" and to `STAFF_NAMES` (a Worker secret; never put the emails in this public repo).
- **Replies:** `POST /c` takes an optional `parent` (a comment id on the same page); a reply takes its thread's slot.
- **Moderation:** the drawer's "Moderate" link takes the moderator key (secret `MOD_KEY`, the same key as the Congress 2027 service, kept in Darwin Garcia's macOS Keychain under `congress2027-comments-modkey`). With it, every comment shows Delete. Deletes are soft (`deleted_at`).

**Database changes.** `schema.sql` is for a new, empty database only. The live database changes only through the numbered migration files, applied once each through the D1 query API, in order: `migration-0002-email.sql` (October 17, 2026) adds `email` and its index. Apply a migration before deploying the Worker that needs it; the older Worker ignores new columns, so that order is always safe. To undo 0002: `DROP INDEX IF EXISTS comments_email;` then `ALTER TABLE comments DROP COLUMN email;` (D1 Time Travel can also restore any point in the last 30 days).

**Deploying.** The Worker is deployed by hand through the Cloudflare API (no wrangler on this machine), byte for byte from the committed `worker.js` with a SHA-256 check. Its secrets stay on the Worker: `MOD_KEY`, `STAFF_KEY` (also on gnycyouth-staff), `STAFF_NAMES`.

Rollback: remove the staff Worker's `COMMENTS` binding (comments stop; the pages keep working). Redeploying an older `worker.js` alone is not enough: versions before October 17, 2026 check the Origin, which service-binding calls do not carry. Roll back the pages and both Workers together, or not at all. The `email` column can stay either way. To undo the move itself, revert the commit that made it: `assets/comments.js` then shows comments on gnyc.webtekton.com again, through the old staff Worker, and that personal-account database holds the comments as they were on October 18, 2026, without any posted since. Never give either comments Worker a public address again.

**Deploy uploads keep bindings.** A script upload through the API replaces the Worker's bindings unless the metadata lists them or sets `keep_bindings`; check the bindings list after every upload.
